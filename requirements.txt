# Environnement pour le développement LOCAL (scripts racine + dashboard).
# En production, Streamlit Community Cloud utilise dashboard/requirements.txt
# (co-localisé avec le "main file path" dashboard/app.py, prioritaire sur
# celui-ci) — les deux fichiers doivent rester synchronisés (mêmes paquets).
# Voir dashboard/SECRETS.md pour la configuration des secrets côté Cloud.
#
# Volontairement SANS version épinglée (== ) : un pin exact (ex:
# pandas==2.2.2, bcrypt==4.2.0) n'a pas forcément de roue pré-compilée pour
# la version de Python/plateforme réellement utilisée par l'environnement de
# build (Streamlit Cloud notamment) — pip retombe alors sur une compilation
# depuis les sources, qui échoue sans toolchain C/C++/Rust installée. Laisser
# pip choisir la dernière version compatible garantit une roue binaire
# disponible. Contrepartie assumée : une mise à jour amont peut un jour
# changer un comportement (notamment stripe/supabase, dont l'API a déjà
# connu des évolutions par le passé) — à surveiller si un module se met à
# planter après un redéploiement sans changement de code de notre côté.
